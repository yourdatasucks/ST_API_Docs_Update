Authentication

Authentication is required to access most API endpoints. This API uses Bearer Token authentication, typically obtained via an OAuth 2.0 flow or a dedicated token endpoint.

The exact method for obtaining an access token ({access_token}) will be detailed in the "Getting Started" or a specific "Authentication Guide" section of the main documentation (see Getting Started).

Using the Access Token

Once you have an access token, include it in the Authorization header of your API requests, prefixed with "Bearer ":

Authorization: Bearer {your_access_token}

Token Endpoint (Example)

If the API provides a direct token endpoint (e.g., for server-to-server integrations or password grants), it might look like this. Note: OAuth 2.0 authorization code flow is generally preferred for user-facing applications.

POST /oauth/token (Example for Password Grant)

This is just an example. The actual grant type and parameters will depend on the API's OAuth 2.0 implementation. Password grant is often discouraged for security reasons.

Request Body (application/x-www-form-urlencoded)

  • grant_type: password
  • client_id: your_client_id
  • client_secret: your_client_secret (if confidential client)
  • username: user_email_or_username
  • password: user_password
  • scope: (optional) requested scopes

Example Request

POST /oauth/token
Host: auth.api.example.com
Content-Type: application/x-www-form-urlencoded

grant_type=password&client_id=abc123xyz&username=user@example.com&password=securepassword123

Response (Success - HTTP 200 OK)

{
    "access_token": "eyJhbGciOiJSUzI1NiIs...",
    "token_type": "Bearer",
    "expires_in": 3600, // In seconds
    "refresh_token": "def456uvw...", // Optional, if refresh tokens are supported
    "scope": "read write" // Granted scopes
}

Response (Error - e.g., HTTP 400 Bad Request or 401 Unauthorized)

{
    "error": "invalid_grant",
    "error_description": "Invalid username or password."
}

Token Validation / User Info (Example)

Some APIs provide an endpoint to validate a token or get information about the authenticated user.

GET /oauth/userinfo (or /me, /connect/userinfo)

Requires a valid Bearer token in the Authorization header.

Request

GET /oauth/userinfo
Authorization: Bearer {access_token}

Response

{
    "sub": "user123", // Subject - unique user identifier
    "name": "John Doe",
    "email": "john.doe@example.com",
    "user_id": 77,
    "permissions": ["read:contacts", "write:deals"]
    // ... other user claims
}

Token Expiration and Refresh

Access tokens are typically short-lived. If the API supports refresh tokens (obtained during the initial token grant), your application should use the refresh token to obtain a new access token before the current one expires, without requiring the user to re-authenticate.

Refer to the primary API documentation for specifics on the OAuth 2.0 flows supported, client registration, and token management best practices.
